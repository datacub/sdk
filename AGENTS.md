# AGENTS.md

Two independent npm packages in one repo. Bun workspaces, TypeScript, no runtime dependencies.

| Path | What |
|---|---|
| `packages/web` | `@datacub/web`, browsers. `src/index.ts` is the SDK, `src/global.ts` the script-tag wrapper, `src/scrub.ts` the privacy filter, `src/flags.ts` / `feedback.ts` / `insights.ts` opt-in modules. `types/` is generated by the build and committed |
| `packages/react-native` | `@datacub/react-native`, beta. `src/index.ts` is the SDK, `src/scrub.ts` the privacy filter, `src/navigation.ts` the React Navigation helper |
| `skills/datacub/SKILL.md` | The guide coding agents follow to install datacub in a customer's app. Keep it in step with the public API |
| `examples/` | A Vite app CI builds against `packages/web`, and an Expo Router layout |

```sh
bun install
bun run lint && bun run typecheck && bun run test     # everything, fast
bun run --cwd packages/web test:browser               # Playwright, Chromium/Firefox/WebKit
bun run --cwd packages/react-native test:hermes       # Hermes VM; test:bundle for Metro
bun run build                                         # dist/, fails over each size budget
```

Rules:
- Don't break either public API or the batch format the ingestion server accepts. The packages share nothing at runtime; `scrub.ts` is copied on purpose.
- Never collect form values, passwords, card numbers, national IDs, tokens or device identifiers, and no fingerprinting. Consent, revoke and Global Privacy Control must keep working.
- Never republish a version. React Native stays beta (`0.1.0-beta.N`, npm `next`) until it is tested on real devices.
- Conventional commit titles. `fix:` and `feat:` release the package whose files they touch: release-please bumps its version and CHANGELOG, merges its own release PR and the workflow publishes to npm with provenance. `chore:` releases nothing. Nothing is published by hand.
